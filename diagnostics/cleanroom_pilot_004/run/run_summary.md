# PREFREEZE_DIAG_004 — source-bounded diagnostic report

## Scope and method

This is a bounded pre-freeze diagnostic under `PROTOCOL.md` draft-0.8.4, not a literature sweep. Only the seven PDF assets supplied in `sources/` were used: six main articles and the supplied Tsushima et al. supplement. No search, citation expansion, process search, or external retrieval was performed. The registered-run preflight was intentionally inapplicable to this draft; canonical `preflight.py --mode pre-freeze` passed its package/schema audit while reporting the draft's expected unresolved freeze fields.

Each physical experiment was audited for functional structure before comparison atomization. Rows represent paper × experiment × X→Y comparisons. Factorial-functional effects were kept intact where scalar decomposition would destroy the focal mapping. Two physical experiments were retained as support-only and received no comparison row: Ben-Haim Experiment 5 and Lin & Murray Experiment 3. Persaud's single physical experiment legitimately yields two scalar rows because metacognitive calibration and regional BOLD are distinct outputs; the BOLD row is F-not-meaningful.

It nevertheless exits nonzero on exactly two decision-log references:

- `PREFREEZE_DIAG_004_D000031` → support-only experiment `P000001_E05`
- `PREFREEZE_DIAG_004_D000040` → support-only experiment `P000004_E03`

This exposes a pre-freeze execution-contract inconsistency. `AGENTS.md` requires physical experiment groups and pre-atomization assessments to be enumerated and logged, while also requiring a supporting experiment to receive no comparison row unless it independently answers an X→Y question. The current validator treats every experiment-level decision target as if it must appear in `experiments_master.csv`, which has no experiment-group table and contains comparison rows only. Inventing placeholder comparisons would violate the scientific protocol, and deleting append-only audit events would violate execution provenance. The diagnostic therefore preserves the scientifically correct support-only status and records this validator failure rather than fabricating eligibility.

The run remains `paused` at `final-validation`, not registered-sweep `complete`. Search frontiers remain untouched because search was expressly prohibited and sweep completion criteria do not apply to this source-bounded diagnostic.
